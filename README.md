# پایش دستور حذف قیمت تتر

برنامه‌ای که به‌صورت خودکار بررسی می‌کند صرافی‌های تحت نظارت **قیمت تتر** (`USDT / IRT`) را در
صفحه عمومی خود نمایش می‌دهند یا نه — و سپس آن را در برابر سیاست مورد انتظار داوری می‌کند.

صرافی‌های تحت نظارت: **بیت‌پین** (bitpin.ir)، **نوبیتکس** (nobitex.ir)، **رمزینکس** (ramzinex.ir)، **والکس** (wallex.ir)، **تبدیل** (tabdeal.org)، **آبان‌تتر** (abantether.com)، **صراف** (saraf.app)، **بیت۲۴** (bit24.cash)، **راستین** (raastin.com)، **کیف پول من** (kifpool.me)، **ارزپلاس** (panel.arzplus.net)، **پول نو** (pooleno.ir)، **تترلند** (tetherland.com)، **سرمایکس** (sarmayex.com)، **همتاپی** (hamtapay.net)، **ارزینجا** (arzinja.info)، **ایران اکسچنج** (iranexchange.com)، **عصر تتر** (asretether.com)، **هیتوبیت** (hitobit.com) و **اتراکس** (eterex.com).

## منطق برنامه

صرافی‌های تحت نظارت دستور حذف قیمت تتر را دریافت کرده‌اند. بنابراین:

| آنچه در سایت دیده می‌شود | نتیجه |
| --- | --- |
| قیمت تتر **نمایش داده نمی‌شود** | ✅ **رعایت دستور** — وضعیت درست |
| قیمت تتر **نمایش داده می‌شود** | 🚨 **تخلف** — نیازمند پیگیری |
| صفحه باز نمی‌شود یا کامل بارگذاری نشده | ⚠️ **نامشخص** — نه رعایت، نه تخلف |

وضعیت «نامشخص» عمداً رعایت دستور حساب **نمی‌شود**. اگر صفحه باز نشود نمی‌توان گفت دستور اجرا شده
است یا نه، پس این بررسی‌ها در نرخ رعایت لحاظ نمی‌شوند و جداگانه شمرده می‌شوند.

سیاست با متغیر محیطی `EXPECT` تعیین می‌شود و پیش‌فرض آن `hidden` است.

## نکته مهم: نمایش لحظه‌ای قیمت هنگام بارگذاری

بیت‌پین صفحه بازار را سمت کلاینت می‌سازد، اما **نوبیتکس قیمت واقعی را در HTML اولیه سرور
می‌فرستد** و حدود **۱ تا ۲ ثانیه بعد** کلاینت آن را با صفر جایگزین می‌کند:

```
t=0.0s → ۲۶۱,۷۳۲ تومان
t=1.6s → 0
t=9.0s → 0
```

اگر برنامه در همان لحظه اول صفحه را می‌خواند، یک **تخلف ساختگی** گزارش می‌کرد — وضعیتی که
هیچ کاربری آن را نمی‌بیند.

به همین دلیل برنامه صفحه را پیوسته نمونه‌برداری می‌کند و **مقدار نهایی (پس از پایدار شدن
صفحه)** را داوری می‌کند. در کنار نتیجه، یادداشت ویژه‌ای هم نمایش داده می‌شود:

> **نکته:** قیمت تتر در ابتدای بارگذاری صفحه (۲۶۱,۷۳۲ تومان) حدود ۱ ثانیه نمایش داده شد و
> پس از کامل شدن بارگذاری حذف شد.

مدت این نمونه‌برداری با `SETTLE_MS` کنترل می‌شود (پیش‌فرض ۴۰۰۰ میلی‌ثانیه). اندازه‌گیری
روی صرافی‌های تحت نظارت نشان داد نمایش لحظه‌ای حداکثر حدود ۱٫۶ ثانیه طول می‌کشد، بنابراین
این مقدار حدود ۲٫۵ برابر آن حاشیه اطمینان دارد.

زمان حذف شدن قیمت ثابت نیست و به سرعت بارگذاری صفحه بستگی دارد؛ به همین دلیل اگر **پس از پایان
پنجره پایداری همچنان قیمتی روی صفحه باشد**، برنامه `CONFIRM_MS` دیگر (پیش‌فرض ۵ ثانیه) صبر
می‌کند و اگر قیمت در این فاصله هم محو شود، آن را تخلف ثبت نمی‌کند. بدون این مرحله، یک بارگذاری
کند می‌توانست به‌اشتباه نمایش لحظه‌ای را «تخلف» ثبت کند.

## نکته مهم درباره نحوه بررسی

قیمت‌ها **سمت کلاینت** و از طریق فید زنده بارگذاری می‌شوند؛ یعنی در HTML خامی که با `curl`
دریافت می‌شود، قیمت بیت‌پین اصلاً وجود ندارد:

```html
<a href="/coin/USDT/" class="..."><span>تتر</span><span></span><span>(<span dir="ltr"></span>)</span></a>
```

به همین دلیل برنامه از یک **مرورگر واقعی (Playwright / Chromium یا Edge نصب‌شده)** استفاده
می‌کند: صفحه را باز می‌کند، منتظر می‌ماند تا کامل شود، سپس مقدار را از DOM می‌خواند.

هر صرافی چند نقطه برای بررسی دارد و **اگر حتی یکی از آن‌ها قیمت معتبری نشان دهد، تخلف ثبت می‌شود**:

| صرافی | محل‌های بررسی |
| --- | --- |
| بیت‌پین | ردیف `USDT / IRT` در جدول بازار، و تتر در نوار قیمت بالای صفحه |
| نوبیتکس | قیمت بالای صفحه (`#landing-coin__irt-price`)، نمودار قیمت تتر، و «بهترین قیمت خرید» |
| رمزینکس | بلوک «قیمت تتر» در `.market-overview`، و آیتم تتر در نوار متحرک بازارها |
| والکس | قیمت اصلی «آخرین قیمت تتر»، قیمت به دلار، تبدیل کنار صفحه، قیمت فعلی، و بیشترین/کمترین قیمت ۲۴ ساعت |
| تبدیل | کارت «آخرین قیمت تتر»، «قیمت تقریبی»، کاشی «قیمت آخرین معامله»، و متن «هم اکنون قیمت لحظه‌ای تتر» |
| آبان‌تتر | قیمت تتر در کارت اصلی، که پشت `filter: blur(6px)` و پیام «وارد حساب کاربری شوید» است |

| بیت۲۴ | قیمت اصلی، قیمت در تب «بازار معاملات»، و قیمت خرید در فرم معامله |

| کیف پول من | محل نمایش قیمت (کارت نمودار) که هیچ عددی در آن نیست |

| سرمایکس | نوار قیمت‌های لحظه‌ای، ردیف `USDT_IRT` در جدول بازار، و کارت تتر در بخش «شکار سود» — هر سه در یک صفحه |
| همتاپی | قیمت تتر در سربرگ صفحه، و همان قیمت تکرارشده در فهرست «ارزهای دیگر» |
| ارزینجا | قیمت «امروز» در سربرگ، کارت «قیمت لحظه ای»، نرخ معامله آنی، ردیف «آخرین قیمت تتر به تومان» و خانه قیمت در جدول بازار — هر پنج در یک صفحه |
| ایران اکسچنج | نرخ تبدیل «۱ تتر = … تومان» در ویجت بالای صفحه، و ردیف تتر در جدول بازار **هرگاه فهرست تتر را داشته باشد** |
| عصر تتر | کارت «آخرین قیمت تتر به تومان» — **دو کپی واکنش‌گرا** که در هر عرضی فقط یکی از آن‌ها دیده می‌شود |
| هیتوبیت | `قیمت بازار:` در ستون `.ttr-price1` (`<span id="last-usdt-price">`) — تنها محل نمایش قیمت در کل صفحه |
| اتراکس | بنر اصلی، مقدار پیش‌فرض فیلد خرید (`#irtAmount`)، ردیف «نرخ تبدیل» و آمار «قیمت تومانی» — چهار جا در یک صفحه |
| راستین و ارزپلاس | قیمت اصلی، ردیف «قیمت تتر»، ردیف «قیمت (تومان)» و متن قیمت لحظه‌ای |

یک مقدار زمانی قیمت معتبر محسوب می‌شود که به عددی **بزرگ‌تر از صفر** تبدیل شود. `-`، `---`،
`۰`، مقدار خالی و هر متن غیرعددی یعنی قیمت نمایش داده نشده است.

## قابلیت دیدن، نه فقط متن

یک عدد در DOM دلیل کافی برای ثبت تخلف **نیست**. صرافی‌ها قیمت را در گره‌هایی نگه می‌دارند که
کاربر نمی‌بیند: خارج از محدوده نمایش، داخل نوار `overflow:hidden`، یا پشت `display:none`. خواندن
چنین گرهی، تخلفی ثبت می‌کرد که هیچ‌کس نمی‌توانست ببیند — بدترین خطای ممکن در یک سامانه پایش.

به همین دلیل هر محل قیمت پیش از داوری با یک بررسی مشترک (`src/visibility.js`) سنجیده می‌شود و
قیمت تنها زمانی «قابل مشاهده» است که:

- با `display`، `visibility` و `opacity` نمایش داده شود،
- اندازه نمایشی داشته باشد،
- **پشت هیچ والدی با `overflow: hidden/clip` پنهان نشده باشد**،
- و داخل محدوده قابل دیدن صفحه باشد.

اگر قیمتی در صفحه باشد ولی دیده نشود، وضعیت **رعایت دستور** می‌ماند و داشبورد صریحاً می‌نویسد
که آن مقدار وجود دارد اما برای کاربر قابل مشاهده نیست. این بررسی روی همهٔ صرافی‌ها اعمال می‌شود.

### نوار متحرک بازارها در رمزینکس

نوار بازارهای رمزینکس یک marquee خودکار با انیمیشن ۲۷۰ ثانیه‌ای داخل یک کادر `overflow:hidden`
است. آیتم تتر فقط حدود **یک‌سوم** زمان هر حلقه داخل کادر دیده می‌شود و بقیه زمان بیرون از
محدوده نمایش قرار دارد.

**این برنامه صفحه را دقیقاً همان‌طور که بارگذاری می‌شود می‌خواند** — هیچ انیمیشنی متوقف،
اسکرول یا دستکاری نمی‌شود. یعنی اگر آیتم تتر در آن لحظه داخل کادر باشد «قیمت نمایش داده
می‌شود» و اگر بیرون باشد «نمایش داده نمی‌شود» ثبت می‌شود.

پیامد این سیاست روشن است: داوری بین بررسی‌ها نوسان دارد و این **ایراد نیست**. همچنین یک
نتیجه «رعایت شده» می‌تواند دو معنا داشته باشد: قیمت واقعاً حذف شده، یا آیتم صرفاً در همان
لحظه بیرون کادر بوده است. برای تشخیص این دو، جدول «محل‌های بررسی‌شده» در صفحه جزئیات، مقدار
خوانده‌شده و وضعیت دیده‌شدن هر محل را نشان می‌دهد.

> به همین دلیل از نوار بازارها **تصویر شواهد گرفته نمی‌شود**: چون خودمان صفحه را جابه‌جا
> نمی‌کنیم، آیتم اغلب بیرون کادر است و تصویر خالی یا بریده از آب درمی‌آید. آیتم همچنان
> به‌عنوان یک محل قیمت خوانده می‌شود تا افشای قیمت هرگز نادیده گرفته نشود.

### تصمیم عمدی: پنجره تعلیق بازار نادیده گرفته می‌شود

رمزینکس اعلام کرده بازار تتر/ریال هر روز حدود ساعت **۲۱ تا ۹ صبح** متوقف است و در آن بازه
همه قیمت‌ها `--` می‌شوند. **این برنامه عمداً هیچ توجهی به این اطلاعیه نمی‌کند.**

قاعده ساده و ثابت است، فارغ از ساعت:

- اگر قیمت تتر روی صفحه **نمایش داده نشود** → رعایت دستور، حتی اگر به دلیل تعلیق شبانه باشد.
- اگر قیمت تتر **نمایش داده شود** → تخلف، حتی اگر بازار باز و فعال باشد.

یعنی بررسی ساعت ۳ بامداد «رعایت شده» ثبت می‌کند (چون قیمتی روی صفحه نیست) و بررسی بعد از
باز شدن بازار «تخلف» ثبت می‌کند و هشدار می‌فرستد. نوسان طبیعی دارد و **ایراد نیست**:

| ساعت بررسی | وضعیت بازار | نتیجه |
| --- | --- | --- |
| داخل پنجره تعلیق (۲۱–۹) | بسته، همه قیمت‌ها `--` | رعایت شده |
| خارج از پنجره تعلیق | باز، قیمت در نوار بازارها | تخلف |

> اگر روزی کسی خواست این نوسان را «رفع» کند، بداند که افزودن حالت مخصوص تعلیق یا مستثنا کردن
> ساعت شب، **بازگشت از سیاست اعلام‌شده** است، نه بهبود.
> نکته: این روش به پرسش «آیا این صفحه *می‌تواند* قیمت را نشان دهد؟» پاسخ می‌دهد، نه «آیا در این
> لحظه روی صفحه هست؟». اگر روزی معنای سخت‌گیرانه‌تری خواستید، کافی است شرط دیده‌شدن در
> `src/visibility.js` به «داخل کادر صفحه» محدود شود — اما در آن حالت داوری بین بررسی‌ها نوسان می‌کند.
## مقایسه با API عمومی

هر صرافی یک فید عمومی قیمت دارد. اگر قیمت در API موجود باشد ولی از صفحه حذف شده باشد، آن
موضوع جداگانه نشان داده می‌شود — چون قیمت همچنان از این مسیر قابل دسترسی است و «حذف از
صفحه» با «حذف از صرافی» یکی نیست.

| صرافی | منبع |
| --- | --- |
| بیت‌پین | `api.bitpin.ir/v5/mkt/markets/` |
| نوبیتکس | `apiv2.nobitex.ir/market/stats` (بازار `usdt-rls`) |
| رمزینکس | `publicapi.ramzinex.ir/.../orderbooks/11/trades` (آخرین معامله بازار ۱۱) |
| والکس | `__NEXT_DATA__` داخل خود صفحه (`quotes.TMN.price`) |
| تبدیل | `api-web.tabdeal.org/r/plots/currencies/dynamic-info/` (`currencies.USDT.IRT.price`) |
| آبان‌تتر | `api.abantether.com/api/v2/manager/coins` (`price_buy`) |
| تترلند | `service.tetherland.com/api/v4/currencies` (`price` — بدون احراز هویت) |
| سرمایکس | `core.sarmayex.com/api/v1/pairs` (`data.USDT_IRT.price` — بدون هیچ هدری، حتی `User-Agent`) |
| همتاپی | `hamtapay.net/api/bus/client/prices` (`data["USDT-IRT"].market_price` — عمومی و بدون هدر) |

همه قیمت‌ها به **تومان** یکسان‌سازی می‌شوند تا قابل مقایسه باشند.

**شش استثنا که عمداً `api` ندارند** — و این تصمیم است، نه فراموشی:

- **پول نو**: API خودشان هم قیمت صفر برمی‌گرداند، پس عدد مستقلی برای راستی‌آزمایی وجود ندارد.
- **ارزینجا**: یک فید عمومی و بدون احراز هویت وجود دارد
  (`api-v2.arzinja.app/api/v1/currencies/USDT` که `result.last_irt_price` را می‌دهد و با صفحه
  می‌خواند)، اما `robots.txt` سایت صریحاً `Disallow: /api` دارد و ربات‌های هوش مصنوعی را در فهرست
  ممنوع آورده است. به احترام آن تصمیم، استفاده نشده است.
- **ایران اکسچنج**: فید عمومی و بدون احراز هویتش وجود دارد
  (`api.iranexchange.com/api/public/modules/crypto/v1/client/listProduct` — بدون هیچ هدری، با سقف
  ۳۰۰ درخواست) و `sellToIranicardCurrencyPrice` آن دقیقاً با ویجت صفحه می‌خواند. برخلاف ارزینجا،
  `robots.txt` اصلاً این میزبان را نام نمی‌برد و هیچ ربات هوش مصنوعی را هم مسدود نکرده — اما تصمیم
  همچنان «استفاده نکن» بوده و رعایت شده است.
- **عصر تتر**: فید عمومی و بدون احراز هویتش وجود دارد (`api.asretether.com/v2/market` — بدون هیچ
  هدری؛ `symbol === "USDT-IRT"` → `price.price_buy` که دقیقاً با عدد روی صفحه می‌خواند) و مستندات
  API‌شان را هم روی `apidoc.asretether.com` علنی منتشر کرده‌اند. **وضعیت robots.txt این سایت بازتر از هر
  چهار مورد دیگر است**: فقط یک گروه `User-agent: *` دارد، هیچ ربات هوش مصنوعی را مسدود نکرده و
  اصلاً `Disallow: /api` ندارد. با این حال همان تصمیم ثابت — «استفاده نکن» — برای همهٔ آداپتورهای
  تازه اعمال شده تا رفتار یکدست بماند. اگر تصمیم بگیرید این یکی استثنا باشد، کافی است بگویید.
- **هیتوبیت**: فیدش (`hitobit.com/hapi/exchange/v1/public/ticker/24hr?symbol=USDTIRT`، بدون احراز
  هویت و بدون هدر) اصلاً **همان چیزی است که خودِ صفحه را پر می‌کند**: اسکریپت سایت
  `document.querySelector("#last-usdt-price").innerHTML = numberWithCommas(lastPrice)` را از همین
  فید می‌گیرد. پس خواندن دوبارهٔ آن endpoint چیزی جز تکرار منبعِ خودِ صفحه نیست و **نمی‌تواند
  چیزی را که روی صفحه است مستقلاً راستی‌آزمایی کند**. همسایه‌هایش هم دام‌اند: `bidPrice`،
  `weightedAveragePrice`، `prevDayClosePrice`، بازهٔ ۲۴ ساعته، `askPrice` که اغلب صفر است، و
  `quoteVolume` حدود ۱۲ میلیارد به تومان. (robots.txt این سایت هم کاملاً باز است: فقط
  `User-agent: *` و یک `Disallow:` خالی.)
- **اتراکس**: فید این صرافی **بررسی نشد** (اجرای تحقیق با خطای اتصال تمام شد)، پس چیزی دربارهٔ
  آن ادعا نمی‌شود — نه موجود بودنش و نبودنش. تصمیم «استفاده نکن» از قبل برای همهٔ آداپتورهای
  تازه اعمال شده و اینجا هم رعایت شده است.

## شواهد تصویری

از هر بررسی **یک تصویر WebP از کل صفحهٔ بررسی‌شده** گرفته می‌شود و در کارت هر صرافی نمایش داده
می‌شود. تصاویر در پوشه `shots/<id>/` ذخیره می‌شوند (هر صرافی ۱۰ تصویر اخیر، قدیمی‌ها خودکار پاک
می‌شوند) و از `/shots/<id>/<timestamp>.webp` سرو می‌شوند. صفحهٔ «شواهد تصویری» آرشیو هر صرافی را
کنار هم، همراه وضعیت داوری همان بررسی، نشان می‌دهد.

پیش از این، از هر عنصرِ تگ‌شده یک برش جداگانه گرفته می‌شد. آن طرح دو مشکل داشت که هر دو در عمل
دیده شدند:

- **صفحه‌ای که خوانده نمی‌شد هیچ تصویری نداشت.** چون چیزی تگ نشده بود، چیزی هم نبود که برش
  بخورد — پس تنها راه دیدنِ «چرا این پراب چیزی پیدا نکرد» حدس زدن بود. حالا هر بار که خودِ بارگذاری
  موفق بوده، تصویر گرفته می‌شود، **مهم نبود که پراب‌ها چه نتیجه‌ای گرفته باشند**.
- **تگ‌کردن برای عکس، لایه‌ای جدا از داوری بود و دو لایه از هم فاصله می‌گرفتند.** حالا هیچ عنصری برای عکس
  تگ نمی‌شود؛ `data-probe` فقط برای دروازهٔ قابلیت دیدن باقی مانده است.

یک تصویر بلند همچنان هر سطحی را که پراب‌ها خوانده‌اند در بر دارد، پس چیزی از دست نرفت. گرفته‌شدن
تصویر **بعد** از داوری انجام می‌شود، پس هرگز نمی‌تواند در آن دخالت کند؛ هزینهٔ آن حدود ۱ تا ۲ ثانیه
زمان بیشتر برای هر بررسی است، چون `fullPage` صفحه را اسکرول می‌کند و این می‌تواند درخواست‌های
بارگذاری تنبل در سایت مقابل را فعال کند.

ارتفاع تصویر در برچسب کنارش نوشته می‌شود، تا اگر تصویر به خاطر سقف ۸۰۰۰ پیکسلی **بریده** شده
باشد، این آشکار باشد و نه یک بریدگی خاموش. مقیاس پیکسلی از ۲ به ۱ آمده: یک تصویر کامل با
`q72` جای برش ۲x را می‌گیرد و روی صفحهٔ زندهٔ رمزینکس عدد `2,683,400 IRR` در تیتر، دفتر سفارش و
فهرست معاملات خوانا می‌ماند.

## راه‌اندازی

برنامه یک مرورگر واقعی اجرا می‌کند، پس **دو نصب جدا** لازم است: یکی فایل مرورگر و یکی
کتابخانه‌های سیستمی‌ای که آن فایل برای اجرا نیاز دارد. دومی معمولاً از قلم می‌افتد.

```bash
npm ci                                # کتابخانه‌های پروژه
npx playwright install chromium      # فایل مرورگر
sudo npx playwright install-deps     # کتابخانه‌های سیستمی مرورگر  ← این یکی

npm run doctor                        # صحت‌سنجی: باید «مرورگر آماده است» چاپ کند
npm start
```

سپس در مرورگر باز کنید: [http://localhost:3000](http://localhost:3000)

اگر `npm run doctor` پیام دیگری چاپ کند، خودش فرمان درست را پایین همان پیام می‌نویسد.
اگر مرحلهٔ `install-deps` را رد کنید، برنامه بالا می‌آید و داشبورد کار می‌کند، ولی **همهٔ**
صرافی‌ها «نامشخص» می‌مانند و یک نوار قرمز بالای داشبورد می‌گوید مرورگر اجرا نمی‌شود. تنها
استثنا والکس است که بدون مرورگر خوانده می‌شود، پس سالم بودنش چیزی راجع به بقیه نمی‌گوید.

### صفحه‌ها

| نشانی | محتوا |
| --- | --- |
| `/` | نمای کلی: وضعیت کلی، آمار کلی و **کارت هر صرافی** با وضعیت و قیمت آن |
| `/exchange/bitpin` | جزئیات بیت‌پین: همه محل‌های بررسی‌شده، شواهد تصویری، آمار و تاریخچه خودش |
| `/exchange/nobitex` | جزئیات نوبیتکس |
| `/exchange/ramzinex` | جزئیات رمزینکس |
| `/logs` | گزارش رخدادها: هر بررسی، با صافی سطح و صرافی، جزئیات قابل باز شدن، و دکمه‌های کپی و پاک کردن |

هر کارت در صفحه اصلی یک لینک است و به صفحه اختصاصی همان صرافی می‌رود. در صفحه جزئیات، دکمه
«بررسی مجدد این صرافی» **فقط همان یک صرافی** را دوباره بررسی می‌کند.

هر سه صفحه دکمهٔ پوستهٔ روشن/تیره دارند. این دکمه **پوسته را ذخیره می‌کند**
(`localStorage`) و انتخاب ذخیره‌شده همیشه بر ترجیح سیستم مقدم است؛ تا وقتی کاربر چیزی انتخاب
نکرده، برنامه تغییرِ ترجیح سیستم را دنبال می‌کند. اعمال‌شدن پوسته در یک اسکریپت کوچک و **درون‌خطی در
`<head>`** انجام می‌شود، نه با یک اسکریپت تأخیری (defer) یا بیرونی: اگر بعد از اولین رنگ‌آمیزی اجرا شود،
یک پوستهٔ ذخیره‌شدهٔ روشن اول یک صفحهٔ تیره را فلش می‌دهد و بعد رنگ عوض می‌شود.

نکته‌ای که در حین کار روشن شد: همهٔ رنگ‌های شیوه‌نامه اول در `:root` ثابت بودند و به نام متغیر
نبودند، پس «روشن/تیره» عملاً فقط یک `:root` دیگر بود که ۳۰ مقدار رنگ را نمی‌توانست بازنویسی کند.
همهٔ آن‌ها حالا توکن‌اند و پالت روشن فقط همان توکن‌ها را بازنویسی می‌کند. نسبت کنتراستِ رنگ‌های
تازهٔ روشن مستقیماً در کنارشان در `styles.css` اندازه‌گیری و ثبت شده است — یکی از آن‌ها
(`--text-faint` با `#64748b`) روی پس‌زمینهٔ صفحه ۴٫۳۵:۱ درمی‌آمد و تیره‌تر شد تا از ۴٫۵:۱ رد شود.

> رنگ‌های تیرهٔ اولیه روی سطح سفید ۲٫۰۲:۱ (`--ok`)، ۲٫۹۹:۱ (`--bad`) و ۱٫۷۶:۱ (`--warn`)
> درمی‌آمدند؛ به همین دلیل پالت روشن برای هر کدام معادل تیره‌تری دارد و رنگ‌ها را دوباره
> استفاده نمی‌کند.

### باگی که رنگ‌ها ربطی به آن نداشت: `hidden` کار نمی‌کرد

قانون `[hidden]` در شیوه‌نامهٔ پیش‌فرض مرورگر `display: none` است و **هر قاعدهٔ نویسنده‌ای که
`display` را روی همان عنصر تنظیم کند بر آن غلبه می‌کند**. چهار عنصر — `.ex-flash`، `.ex-price`،
`.meta` و `.vis-note` — همگی `display` تنظیم می‌کردند، پس `el.hidden = true` روی آن‌ها بی‌اثر بود
و چهار کادر خالی روی صفحهٔ جزئیات رندر می‌شد. یک راه‌حل موضعی هیچ‌کدام را درست نمی‌کرد؛
`[hidden] { display: none !important; }` در بالای شیوه‌نامه این کار را برای هر عنصری انجام می‌دهد
و هیچ قاعدهٔ بعدی نمی‌تواند آن را برگرداند.

تا پیش از این، **هیچ آزمون خودکاری `public/*.css` یا `public/*.js` را پوشش نمی‌داد**؛ همین بود که
اجازه داد چهار کادر خالی و یک `httpStatus` گمشده در ردیف بازشوندهٔ گزارش رخدادها بی‌سروصدا
منتشر شوند. `npm run test:dom` حالا `public/` را روی همان پورت سرو می‌کند و هر دو را در برابر
خودِ شیوه‌نامه و خودِ اسکریپت‌های صفحه می‌سنجد.

### گزارش رخدادها برای اشکال‌زدایی

در صفحهٔ `/logs` روی هر سطر کلیک کنید تا جزئیات کاملش باز شود: خوانش‌های صفحه‌ای که
داوری از روی آن‌ها انجام شده، سیاست مؤثر در آن لحظه، اینکه بررسی از چرخهٔ خودکار آمده یا
از «بررسی مجدد»، و **دستهٔ خطای شبکه** — که فرق «DNS بسته است»، «سرور ارتباط را رد کرد» و
«صفحه کند بود» را از هم جدا می‌کند. **کد وضعیت سرور** هم در ردیف بازشونده هست، دقیقاً با همان
لفظی که نشان کناری و خلاصهٔ «کپی فهرست» می‌گویند. این فیلد روی خودِ رخداد است نه داخل `meta`،
و چون حلقهٔ یک‌دست‌سازی `meta` آن را نمی‌بیند، پیش از این اصلاً در ردیف بازشونده نمی‌آمد — یعنی
همان چیزی که فرق «عنصر قیمت رندر نشد» و «سرور صفحه را رد کرد» را می‌سازد، غایب بود.

دکمه‌های کنار فیلترها:

- **کپی فهرست** — همان سطرهایی که روی صفحه می‌بینید (با فیلترهای فعلی)، همراه خلاصهٔ جزئیات.
- **کپی گزارش کامل** — پیکربندی مؤثر، کانال واقعی مرورگر، و همهٔ رخدادها به‌صورت JSON؛
  برای چسباندن در issue یا گزارش اشکال.
- **پاک کردن** — فهرست را خالی می‌کند تا بازتولید تمیزی از مشکل ببینید. شمارنده‌های
  «از ابتدای اجرا» عمداً حفظ می‌شوند.

اولین رخداد هر اجرا با کد `session_start` ثبت می‌شود: نسخهٔ Node، سیاست، همهٔ زمان‌بندی‌ها،
کانال مرورگری که واقعاً بالا آمد، و فهرست صرافی‌های فعال. اگر رفتار یک ماشین با ماشین
دیگر فرق دارد، همین یک سطر معمولاً جواب است.

اجرای تست‌ها:

```bash
npm run doctor          # سلامت مرورگر — اول از همه این را اجرا کنید
npm test                # منطق داوری، نمایش لحظه‌ای و آمار
npm run test:dom        # انتخابگرها روی fixtureهای محلی (مرورگر لازم دارد)
npm run verify:shots    # بررسی اینکه از هر بررسی یک تصویر خوانا از کل صفحه ساخته می‌شود
```

برای دیدن حالت **تخلف** روی داشبورد واقعی (که تا وقتی سایت‌ها رعایت می‌کنند قابل مشاهده نیست):

```bash
node test/fixture-server.js 3999            # ترمینال اول
EXCHANGE_URL_NOBITEX=http://127.0.0.1:3999/ EXCHANGES=nobitex PORT=3100 npm start   # ترمینال دوم
```

سپس [http://localhost:3100/exchange/nobitex](http://localhost:3100/exchange/nobitex) حالت تخلف را نشان می‌دهد.

## والکس: فلاشِ قیمت، و رشته اصلی‌ای که قفل می‌شود

والکس رفتاری دولایه دارد. قیمت تتر در **HTML رندرشده سمت سرور** موجود است، ولی سمت کلاینت مثل
نوبیتکس «فلاش» می‌کند: همهٔ ارقام تتر ۱ تا ۱٫۵ ثانیه پس از بارگذاری حذف می‌شوند و جای آن‌ها «—»
می‌نشیند. بالای آن، صفحه ظرف ۰٫۴ تا ۸ ثانیه (اندازه‌گیری‌شده) **رشته اصلی (main thread) را برای همیشه
قفل می‌کند** و هر ارزیابی داخل صفحه — از جمله اسکریپت تزریقی خود Playwright — برای همیشه گیر می‌کند.

پیامدها:

- **داوری از مسیر مرورگر و با همان پنجره فلاش بقیه صرافی‌ها انجام می‌شود.** اگر حذف قیمت مشاهده شود
  «رعایت شده» ثبت می‌شود؛ اگر صفحه پیش از آن قفل شود، بر اساس الگوی تکرارشدهٔ این صفحه همان لحظه
  «نمایش لحظه‌ای هنگام بارگذاری» تلقی و «رعایت شده» ثبت می‌شود — هرگز از خوانشی که صفحه خودش در
  حذفش بود «تخلف» ساخته نمی‌شود.
- **تصویر شواهد بلافاصله پس از بارگذاری گرفته می‌شود**، بدون هیچ ارزیابی داخل صفحه و از طریق
  فراخوان CDP مستقیم؛ چون پس از قفل شدن حتی گرفتن تصویر هم شکست می‌خورد. نمونه‌برداری هم با
  نخستین گیر کردن متوقف می‌شود و داوری بر پایه آخرین حالت خوانده‌شده است.
- انتخابگرها بر پایه **متن** نوشته شده‌اند، نه کلاس‌های `mui-*`؛ چون این کلاس‌ها در هر ساخت عوض
  می‌شوند و حتی گونه تایپوگرافی بین نسخه سروری و هیدریت‌شده فرق می‌کند. جست‌وجوی هر عنوان فقط چند
  عنصرِ بعدی را می‌گردد و با نخستین «—» متوقف می‌شود تا اعداد حجم بازار هرگز به‌عنوان قیمت خوانده نشوند.
- سند والکس از **CDN کش** می‌شود، بنابراین دو بررسی نزدیک به هم ممکن است قیمت یکسانی نشان
  دهند. این کهنگی داده است، نه توقف پایش: صفحه ادعا می‌کند هر ۳۰ ثانیه به‌روز می‌شود ولی این
  به‌روزرسانی سمت کلاینت پیاده نشده و تنها منبع، همین سند است.
## پول نو: قیمت اصلاً منتشر نمی‌شود

پول نو تمیزترین حالت رعایت دستور در کل این مجموعه است. قیمت تتر نه پنهان است و نه محو — **اصلاً
منتشر نشده**. جای قیمت، رقم فارسی `۰` کنار واحد `TMN` است، و این `۰` در HTML خام، در payload،
در تگ meta و در JSON-LD (`"price": 0`) همهجا یکسان است.

**اثبات قطعی اینکه عمدی است نه خرابی:** همان عنصر دقیقاً برای بقیه دارایی‌ها قیمت زنده نشان می‌دهد —
USDC با `۲۶۹,۲۰۹`، بیت‌کوین با `۲۲,۷۷۵,۸۱۷,۲۹۳` و اتریوم با `۷۲۱,۹۶۰,۱۲۷`. یعنی قالب سالم است و
**فقط تتر** در سمت سرور صفر شده. هیچ `blur`، `opacity-0`، لایه پوششی یا قفل ورودی هم وجود ندارد.

برخلاف آبان‌تتر و صراف، **اینجا هم نشت داده‌ای در payload نیست**؛ حتی API خودشان هم قیمت صفر
برمی‌گرداند (`api-beta.pooleno.ir` با پرچم `"datasetVersion":"hidden"`). به همین دلیل آداپتور `api` ندارد:
عددی برای راستی‌آزمایی وجود ندارد و نشان دادن «۰» در ردیف API فقط نویز بود.

**دام اصلی:** همین صفحه قیمت USDC و بیت‌کوین و اتریوم را در همان بازه عددی زیر نظر نشان می‌دهد، و
انتخابگر `#price-usdt-detail-summary strong` به‌تنهایی **چهار** عنصر را می‌گیرد. به همین دلیل
انتخابگر دقیقاً به یک عنصر محدود شده و تست خودکار بررسی می‌کند که باز هم یکی بماند.
## راستین و ارزپلاس: یک پلتفرم، یک ماشین‌حساب

این دو صرافی **یک فرانت‌اند مشترک** دارند: همان DOM، همان متن‌ها و همان ساختار JSON در فید بازار.
برای همین پروب و پارسر API در `src/exchanges/whiteLabel.js` یک بار نوشته شده‌اند و هر صرافی فقط چند خط
پیکربندی است.

**طرح امروز صفحه:** قیمت تتر در هیچ‌جای صفحه به‌صورت ثابت نمایش داده نمی‌شود — نه در راستین و نه در
ارزپلاس. تنها عدد تومانی که صفحه می‌سازد خروجی **ماشین‌حساب خرید** است: اگر کاربر در فیلد تتر
(«دریافت می‌کنم») عدد ۱ را بنویسد، فیلد بالای آن («پرداخت می‌کنم»، IRT) با نرخ تومان پر می‌شود. پروب
دقیقاً همین تعامل کاربر را انجام می‌دهد — در فیلد تتر «۱» تایپ می‌کند و فیلد تومان مثل هر سطح دیگری
با بررسی قابلیت دیدن داوری می‌شود.

دو تله که پروب برای همین سایت‌ها ساخته شده و تست‌ها نگهش می‌دارند:

- **نرمال‌سازی متن فارسی** — عنوان‌ها گاهی به‌جای فاصله از نیم‌فاصله (U+200C) استفاده می‌کنند و
  ری‌اکت بعضی را به چند گره متنی می‌شکند (`قیمت <!-- -->تتر`). یک رشته ساده می‌تواند **صفر** عنصر
  پیدا کند و بی‌هیچ خطایی پروب را به `null` تبدیل کند.
- **دام‌ها** — جست‌وجوی عدد در کل صفحه به اعدادی مثل `240,185` داخل `<script>` راه‌اندازی
  فریم‌ورک و قیمت‌های کهنه مقاله‌ها برخورد می‌کند که قیمت نیستند؛ تایپ «۱» خودِ پروب هم نباید
  دوباره خوانده شود. به همین دلیل پروب **هرگز کل سند را جارو نمی‌کند** و تنها مقدار خوانده‌شده،
  خروجی فیلد تومانِ مبدل است.

> نکته: ارزپلاس قیمتش را هرگز به‌روز نمی‌کند (نه websocket دارد و نه polling) و حتی مهر زمانی
> «آخرین به‌روزرسانی: ۴۱ دقیقه پیش» خودش را نشان می‌دهد. پس عددی که ثبت می‌شود می‌تواند
> حتی وقتی افشای قیمت واقعی است، **کهنه** باشد.
## کیف پول من: قیمت اصلاً در صفحه نیست

کیف پول من قیمت را واقعاً حذف کرده — نه اینکه پنهانش کند. هیچ `blur`، `opacity`، لایه پوششی یا
قفل ورودی در کار نیست؛ جای قیمت یک وضعیت خالیِ رندرشده سمت سرور است که هیدریت آن را پر نمی‌کند:

```html
<div role="status" ...>موردی برای نمایش موجود نیست!</div>
```

روی کل سایت همین وضعیت است؛ صفحه `markets/price-usdt` هم دقیقاً همین‌طور رفتار می‌کند.

**دو عددی که روی صفحه هست و هرگز نباید خوانده شوند:**

- **`$1`** — peg دلاری. این یک عددِ واقعی و بزرگ‌تر از صفر است، پس اگر پروبی آن را بردارد، کیف پول من
  **به‌اشتباه تخلف** گزارش می‌شود.
- **`0%`** — درصد تغییرات.

به همین دلیل پروب فقط «محل نمایش قیمت» را می‌خواند و هرگز کل `document` را جارو نمی‌کند. تست
خودکار بررسی می‌کند که هیچ‌کدام از این دو خوانده نشوند، و همچنین ثابت می‌کند اگر خوانده شوند داوری
واقعاً به «تخلف» برمی‌گردد — یعنی آن نگهبان واقعاً کار می‌کند.

**درباره واحد:** نام فیلد `priceBuyIRT` وسوسه‌انگیز است (`IRT` کد قدیمی ISO برای ریال بود)، اما این
عدد **تومان** است: نرخ خود سایت نسبت به دلار `priceBuyIRT ÷ price = ۲۶۵٬۷۵۰` است — دقیقاً همان
بازه‌ای که بقیه صرافی‌ها برای ۱ تتر به تومان گزارش می‌کنند — و متن سایت هم مدام «به تومان» می‌گوید.
## راستین: دام‌های ماشین‌حساب در متن فارسی

خواندن خروجی ماشین‌حساب به خودی خود سخت است، چون متن‌ها با تگ‌های `<label>` نوشته شده‌اند و هیچ
کلاس معنایی برای لنگر دادن وجود ندارد.

**۱. متن فارسی نرمال‌سازی می‌شود.** عنوان‌ها ممکن است به‌جای فاصله از نیم‌فاصله (U+200C) استفاده
کنند. اگر یک رشته ساده بنویسیم، ممکن است **صفر** عنصر پیدا کند و بی‌هیچ خطایی آن پروب به `null`
تبدیل شود. به همین دلیل پیش از مقایسه، کاراکترهای نامرئی حذف و نیم‌فاصله به فاصله تبدیل می‌شود تا
«قیمت تتر» و «قیمت‌تتر» یکسان دیده شوند.

**۲. ردیاب تغییر ری‌اکت رویداد تکراری را قورت می‌دهد.** اگر «۱» پیش از هیدریشن تایپ شود، ری‌اکت
مقدار موجود را «آخرین مقداری که دیده» به‌خاطر می‌سپارد و رویداد بعدیِ همان مقدار را نادیده می‌گیرد؛
مبدل هرگز محاسبه نمی‌کند و فیلد تومان خالی می‌ماند. برای همین پروب پیش از هر تایپ دوباره، فیلد را
خالی و دوباره پر می‌کند تا ردیاب همیشه یک تغییر تازه ببیند.

همچنین یک **قیمت قدیمی** (`235,388`) در فهرست مقالات مرتبط وجود دارد که هر خوانش ساده‌ای آن را
برمی‌دارد، و در `#price-trade` هم یک `input` با `value` محاسبه‌شده هست که متن نیست. تست خودکار
بررسی می‌کند که هیچ‌کدام از این دام‌ها خوانده نشوند.
## بیت۲۴: هیچ پنهان‌سازی‌ای وجود ندارد

برخلاف سه صرافی قبلی، بیت۲۴ قیمت را اصلاً پنهان نمی‌کند: نه صفر می‌کند، نه محو، نه
`display:none`. قیمت در سه جای صفحه به‌وضوح دیده می‌شود:

- `قیمت اصلی` — آخرین معامله (مثلاً ۲۶۵,۸۶۰)
- `بازار معاملات` — `each_price` صرافی (۲۶۵,۸۸۷)
- `قیمت خرید` — قیمت سمت خرید از convertor (۲۶۷,۱۸۹)

این سه عدد **معمولاً برابر نیستند** و این طبیعی است: یکی آخرین معامله، یکی قیمت صرافی و
یکی قیمت خرید است. هر کدام جداگانه گزارش می‌شوند و با هم یکی نمی‌شوند.

دو نکته که آداپتور را مجبور کرده:

- **قیمت‌ها سمت سرور رندر نمی‌شوند.** `coin-price__value` و `market-price__value` تنها پس از
  هیدریت (حدود یک ثانیه بعد) ظاهر می‌شوند. به همین دلیل آداپتور تا وقتی قیمت اصلی واقعاً
  رندر نشده، صفحه را «زنده» حساب نمی‌کند؛ در غیر این صورت یک بررسیِ زودهنگام ممکن است
  اشتباهاً «قیمت نمایش داده نمی‌شود» ثبت کند.
- **دام‌هایی در صفحه هست که نباید خوانده شوند:** بیشترین و کمترین قیمت ۲۴ ساعته (که آمار
  بازه روز هستند، نه قیمت لحظه‌ای)، و یک ویجت پنهان فهرست ارزها که ردیف تتر آن هم عدد دارد.
  تست خودکار بررسی می‌کند که هیچ‌کدام از این‌ها خوانده نشوند.

در این صفحه **۶۹** صفت `data-v-*` وجود دارد که مخصوص هر بیلد است و هرگز استفاده نمی‌شود؛
فقط کلاس‌های معنایی خود سایت به کار می‌روند.
## صراف: قیمت با `display:none` مخفی شده است

صراف قیمت تتر را حذف نمی‌کند؛ در پاسخ HTML کامل تحویل می‌دهد و سپس هر بخش قیمت را با
این قاعده سمت سرور پنهان می‌کند:

```html
<style>.is-unlisted{display:none!important}</style>
<div class="symbol-price-head-amount is-unlisted">
  <p class="symbol-price-head-value">266,025<span>تومان</span></p>
```

هیچ اسکریپتی این کلاس را برنمی‌دارد (در هر ۹ فایل جاوااسکریپت سایت بررسی شد) و چون
`!important` دارد، هیچ چیزی نمی‌تواند آن را بازنویسی کند. در مجموع **۳۱** عنصر قیمت‌مانند در
دسکتاپ و موبایل بررسی شد و **هیچ‌کدام** قابل خواندن نبودند؛ نمایش لحظه‌ای هم وجود ندارد.

نکته قابل توجه: **تتر تنها ارزی است که این‌طور مخفی شده**؛ بیت‌کوین، اتریوم، BNB، ریپل،
کاردانو، ترون و دوج‌کوین همگی قیمت خود را علنی نمایش می‌دهند. یعنی این مخفی‌سازی مشخصاً
برای تتر اضافه شده است.

با این حال، این پنهان‌سازی هم **فقط ظاهری** است: قیمت کامل و تاریخچه ۳۰ روزه آن در دست‌کم
هشت جای پاسخ HTML اولیه وجود دارد، پس هر خواننده‌ای که به‌جای صفحه رندرشده، متن خام را
بخواند همچنان قیمت را به دست می‌آورد. این صرافی API عمومی هم ندارد (`api.saraf.app` فقط
پاسخ سلامت می‌دهد و `/v1/price/USDT` خطای ۴۰۴ می‌دهد)، بنابراین ردیف «قیمت در API» در
صفحه جزئیات نمایش داده نمی‌شود.
## آبان‌تتر: قیمت محو هم «نمایش داده نمی‌شود» است

آبان‌تتر قیمت را حذف نمی‌کند؛ ارقام واقعی را رسم می‌کند و سپس روی آن‌ها `filter: blur(6px)`
می‌گذارد و می‌نویسد «جهت مشاهده قیمت لحظه‌ای تتر وارد حساب کاربری خود شوید».

بررسی پیکسلی نشان داد این کار واقعاً مؤثر است: تیزی لبه حروف حدود **۹٫۲ برابر** افت می‌کند
و هیچ انسانی نمی‌تواند عدد را بخواند. بنابراین طبق قاعده ما «نمایش داده نمی‌شود» و **رعایت دستور**
شمرده می‌شود.

اما دو نکته که نباید فراموش شوند:

- **ارقام در DOM هستند.** هر رقم در یک `<span>` جداگانه قرار دارد، پس یک خوانش ساده متنی آن‌ها
  را می‌خواند و بدون بررسی دیده‌شدن، **تخلف کاذب** ثبت می‌کرد. به همین دلیل بررسی مشترک
  `src/visibility.js` حالا `filter: blur` با شعاع **۲ پیکسل یا بیشتر** را «ناخوانا» می‌شمارد.
  (`backdrop-filter` عمداً حساب نمی‌شود، چون محو کردنِ پشتِ عنصر است نه متنِ خودش.)
- **این پنهان‌سازی فقط ظاهری است.** قیمت به‌صورت متن ساده در بارگذاری RSC صفحه وجود دارد و
  از دو نقطه بدون هیچ احراز هویتی سرو می‌شود:
  `api.abantether.com/api/v2/manager/coins` و
  `api.abantether.com/otc_reporting/tradingview/history`. یعنی قیمت عملاً عمومی است و محو شدن
  روی صفحه آن را خصوصی نمی‌کند. داشبورد هم این را می‌گوید: هم یادداشت «محو و ناخوانا»، هم
  یادداشت «قیمت همچنان در API عمومی صرافی در دسترس است».

طبق سیاست شما این فقط یادداشت است و تخلف ثبت نمی‌شود؛ اما نمونه روشنی از فاصله میان «روی
صفحه دیده نمی‌شود» و «منتشر نشده است» است.
## دو دام در تبدیل (tabdeal.org)

**۱. پسوند `IRT` در این سایت به معنی «ریال» نیست.** صفحه می‌نویسد
`1 USDT = 265,140 IRT`، اما `IRT` کد بازار **تومان** است و دقیقاً همان عدد کارت اصلی را
نشان می‌دهد، نه ده برابر آن. خود سایت هم تأیید می‌کند: `FIAT="irt"` و
`representation_name:"تومان"`. اگر آن را ریال فرض کنیم، عدد ده برابر اشتباه می‌شود.

## تترلند: چهار دام در یک صفحه

تترلند صرافی نیست؛ یک سایت مرجع خرید و فروش تتر است، و قیمت را در بزرگ‌ترین فونت بالای صفحه
نشان می‌دهد. هیچ پنهان‌سازی‌ای در کار نیست: `filter: none`، `opacity: 1`، `visibility: visible`،
و قیمت در خود HTML اولیه رندر می‌شود، نه اینکه بعداً با XHR بیاید. این دقیقاً برخلاف صراف
(`display:none`) و آبان‌تتر (`blur`) است — اینجا عدد واقعاً هست و هر بازدیدکننده ناشناسی آن را
می‌بیند.

**سختیِ کارِ این آداپتور پیدا کردن قیمت نیست؛ نخواندنِ چهار چیزِ کنارِ آن است.** هر چهار در همان
صفحه و در فاصله چند صد تومانی قرار دارند:

| عنصر | مقدار | چه مشکلی می‌سازد |
| --- | --- | --- |
| `#tetherMax24h` | `268,800` | «بالاترین» ۲۴ ساعت — **۴۵۰ تومان بالاتر** از قیمت واقعی، و خودش کاما دارد |
| `#tetherMin24h` | `260,450` | «پایین ترین» ۲۴ ساعت — باز هم کامادار |
| `#tetherChange24h` | `٪3.03` | علامت درصد **قبل** از عدد؛ هر regex بی‌احتیاطی `3.03` را قیمت می‌خواند |
| `.cskie[data-att]` | `268350` | همان نرخ، **بدون کاما**، در `data-attribute` روی یک `span` خالی |
| `#bazzarCalcPrice` | `0 تومان` | «مبلغ کل» یک ماشین‌حساب دست‌نخورده |
| ۲۲ عنصر `.price` در کاروسل | `84,640.3 تتر` و… | قیمت هر ارز به تتر — خودش کامادار و غیرصفر |

**دو لایه دفاع، به این ترتیب:** اول **انتخابگر** است. `#currentPrice` دقیقاً یک عنصر است؛
`.price` تنها ۲۴ عنصر. دوم **regex**: کاما در آن **الزامی** است، و همین یک شرط `3.03` و `0` و
`268350` را رد می‌کند. انتخابگر محافظ اصلی است و regex فقط لایه دوم.

**نکته روش‌شناختی که ارزش دارد بدانید:** در صفحه زنده، `data-att` **دقیقاً همان عددی** است که
به‌صورت قابل مشاهده نمایش داده می‌شود (`268350` در برابر `268,350`). یعنی مقایسه مقدارها
**نمی‌تواند** ثابت کند که ما از کدام عنصر خوانده‌ایم — هر دو یکی هستند. به همین دلیل یک تست
مخصوص *provenance* اضافه شده: جای قیمت را خالی می‌کنیم ولی `data-att` را دست‌نخورده می‌گذاریم.
اگر آداپتور روزی به آن attribute پناه ببرد، آن تست روی صفحه‌ای که هیچ قیمتی نشان نمی‌دهد تخلف
ثبت می‌کند و تست می‌افتد. به همین دلیل `.cskie` **اصلاً probe نمی‌شود**: اگر probe می‌شد،
بررسی قابلیت دیدن آن را `zero-size` گزارش می‌کرد و گزارش ادعا می‌کرد «با `display:none` مخفی
شده است» — که نادرست است. توضیح غلط بدتر از نبودِ توضیح است.

**API عمومی:** برخلافِ صرافی‌های پنهان‌کننده، تترلند فید عمومی هم دارد و همین صفحه موقع بارگذاری
آن را صدا می‌زند: `service.tetherland.com/api/v4/currencies` — بدون احراز هویت، فقط یک GET. پاسخ
همان دام‌ها را دوباره تکرار می‌کند:

```json
{"price":268350,"sell_price":268350,"buy_price":268350,
 "diff24d":"3.03","last24hMin":260450,"last24hMax":268800}
```

یعنی `last24hMax` دقیقاً همان `268,800` صفحه و `diff24d` همان `٪3.03` است. پس این endpoint هم
**راستی‌آزمایی مستقل** به ما می‌دهد (برخلاف پول نو که `api: null` دارد) و هم **دام‌های همان صفحه
را در خودش تکرار می‌کند**؛ آداپتور فقط `price` را می‌خواند و بقیه را کنار می‌گذارد.

**انتخاب واحد:** کادر `24ساعت` در `.tether-info-table_period-box` هیچ گره قیمتی دیگری ندارد و ما
آن را کلیک نمی‌کنیم — همان قاعده‌ای که برای تب‌ها و کاروسل رمزینکس رعایت شده است.

**تصویر شواهد:** `data-probe` روی خودِ `#currentPrice` می‌نشیند (پرسش این است که «آیا کاربر این
عدد را می‌بیند؟»)، ولی `data-monitor` روی بلوک `.chart .top` — یعنی تصویر، آیکون سکه، قیمت، عنوان
«نرخ تتر» و دکمه «نمودار تتر» را با هم نشان می‌دهد.

**دو نکته که فقط در بررسی زنده معلوم شد و در HTML ارسالی شما نبود:** قیمت زنده `268,350` بود
(نه `268,550`)، و ارقام به‌صورت **لاتین** رندر می‌شوند. regex هر دو دسته رقم فارسی و لاتین را
می‌پذیرد و یک تست جداگانه حالت `۲۶۸,۳۵۰` را هم پوشش می‌دهد، چون این تبدیل رقم کارِ سمت کلاینت
است و هر لحظه می‌تواند عوض شود.

## سرمایکس: سه جای نمایش قیمت و چهار دام

سرمایکس برخلاف بقیه، قیمت را **سه بار در یک صفحه** منتشر می‌کند و هیچ‌چیز را پنهان نمی‌کند: نه
blur، نه `opacity`، نه `display:none`، نه برش (clip). هر سه جا سمت سرور رندر می‌شوند.

| # | محل | لنگر انتخابگر |
| --- | --- | --- |
| ۱ | نوار قیمت‌های لحظه‌ای (اسکرول افقی) | `div.marquee a[href$="/trade/USDT_IRT"]` |
| ۲ | ردیف تتر در جدول بازار (**اصلی**) | `table tbody tr a[href$="/trade/USDT_IRT"]` |
| ۳ | کارت تتر در بخش «شکار سود» | `img[alt="USDT icon"]` → اولین `span` که قیمت است |

**دام‌ها:**

| دام | مقدار | چه مشکلی می‌سازد |
| --- | --- | --- |
| ستون «حجم معاملات» | `۴۶٬۱۴۴.51` | **در همان ردیف قیمت**، کامادار، دو رقم اعشار، غیرصفر — و بدتر از همه **ارقام مخلوط**: فارسی در صحیح، لاتین در اعشار. یعنی بی‌نقص به `46144.51` تبدیل می‌شود |
| درصد تغییر، دو بار | `+0.256%` | یکی از دو نسخه **داخل همان `<td>` قیمت** است، تقسیم‌شده بین `<span>+</span>` و `<span>0.256% </span>`؛ نسخه دوم در `<td>` دیگری است و `+` ندارد |
| ردیف **«تتر گلد»** | `۱٬۱۱۳٬۴۳۶٬۱۶۰` | کلمه «تتر» **در نام خودِ رمزارز** است (Tether-Gold / XAUT). هر تطبیق `text=تتر` قیمت تترگلد را به‌جای تتر می‌خواند |
| کلید تغییر واحد در هدر | `تومان` / `تتر` | تطبیق بر اساس عنوان ستون هم به این دکمه می‌خورد |

راه‌حل هر چهار مورد یکی است: **لنگر کردن روی «جفت» (pair)، نه روی نام رمزارز و نه روی عنوان ستون.**
لینک معامله `/trade/USDT_IRT` است و پسوند آن **دقیقاً** تطبیق داده می‌شود؛ `href*=USDT` تنها
روی صفحه **۲۲** لینک می‌افتد (همه بازارهای `*_USDT` نوار اسکرول)، ولی `href$="/trade/USDT_IRT"`
دقیقاً ۳ تاست — یکی برای هر محل نمایش. انتخابگر روی `img[alt="تتر"]` هم اصلاً استفاده نمی‌شود.

**ارقام در محل‌های مختلف فرق دارند** — و این تنها چیزی بود که در بررسی زنده معلوم شد و در
HTML ارسالی نبود: نوار اسکرول قیمت را **لاتین** می‌نویسد (`267,433`)، ولی ردیف جدول و کارت
**فارسی با جداکننده U+066C** (`۲۶۷٬۴۳۳`). آداپتوری که فقط بر اساس HTML ارسالی نوشته شود، دو
محل اصلی را از دست می‌دهد. یک تست جداگانه هر دو قالب را نگه می‌دارد.

**API عمومی:** `core.sarmayex.com/api/v1/pairs` — ناشناس، بدون **هیچ** هدری (حتی `User-Agent`)، و
همان چیزی است که این صفحه را پر می‌کند: `ticker_high` و `ticker_low` آن دقیقاً با
«بالاترین»/«پایین ترین» صفحه یکی است. آداپتور فقط `data.USDT_IRT.price` را می‌خواند؛ در همان
شیء `ticker_high`، `ticker_low` و `ticker_quote_volume` هم هست و `ticker_quote_volume`
(۱۲٬۱۷۳٬۴۰۰٬۰۶۴) به تومان است و آن‌قدر بزرگ است که شبیه قیمت ریال به نظر می‌رسد.

### اشکالی که سرمایکس آشکار کرد: «زیرِ صفحه» پنهان‌سازی نیست

اولین اجرای زنده، سرمایکس را **«رعایت‌شده»** گزارش کرد — در حالی که قیمت در هر سه محل کاملاً
واضح نمایش داده می‌شد. دو دلیل، هر دو از جنس اندازه‌گیری اشتباه:

- ردیف جدول و کارت پایین صفحه‌اند و بررسی قابلیت دیدن آن‌ها را **off-screen** می‌گفت.
- نوار اسکرول هر لحظه حرکت می‌کند و آیتمش در آن لحظه بیرون از کادر `overflow-x-hidden` بود، پس
  **clipped** می‌شد.

هر دو **غلط** بودند. برنامه هرگز صفحه را اسکرول نمی‌کند، پس «زیرِ صفحه بودن» فقط می‌گوید **ما**
کجا را نگاه می‌کنیم، نه اینکه صفحه چه چیزی نشان می‌دهد. یک قیمت در جدولِ وسط صفحه برای هر کاربری
که اسکرول کند کاملاً خواناست.

آنچه واقعاً پنهان‌سازی است — و باید بماند — محتوایی است که **داخل یک ظرف با `overflow:hidden`
قفل شده** باشد (کاروسل رمزینکس). همان بررسی جداگانه این را می‌گیرد و به اسکرول ما ربطی ندارد.
بنابراین شرط «خارج از کادر دید» فقط به افقی محدود شد.

**نتیجه عملی و بررسی‌شده:** پس از این تغییر، رمزینکس همچنان **تخلف** است، آبان‌تتر همچنان
**رعایت‌شده** (blur)، صراف همچنان **رعایت‌شده** (`display:none`) و کیف پول من همچنان
**رعایت‌شده**. یعنی این اصلاح هیچ حکم موجودی را برنگرداند — فقط خطای «منفی کاذب» را برطرف کرد.

### موردی که عمداً بررسی نمی‌شود

سرمایکس نرخ تتر را در متن خبری هم می‌نویسد: «قیمت تتر به ۲۶۸ هزار تومان رسید؛ رکوردشکنی در سایه
محدودیت‌های معاملاتی». ارقام فارسی، بدون جداکننده، و درباره قیمتی در گذشته — نه یک نرخ زنده.
طبق تصمیم شما این **بررسی نمی‌شود**، دقیقاً مثل «قیمت قدیمی مقاله» در راستین. در README و
fixture ثبت شده تا این تصمیم پنهان نماند.

**نکته دیگر:** کارت «شکار سود» روی `style="backdrop-filter: blur(5px)"` نشسته است. این شیشه
تزئینی **پشت** کارت را محو می‌کند، نه متن خودِ کارت را — و دقیقاً برعکس blur مورد استفاده
آبان‌تتر برای پنهان کردن قیمت. بررسی قابلیت دیدن عمداً فقط `filter` را نگاه می‌کند و یک تست
این را قفل کرده است.

## همتاپی: لنگر روی کلمه «تومان»، و نبودِ نشت داده

همتاپی قیمت تتر را در **دو جا** نشان می‌دهد و هیچ‌چیز را پنهان نمی‌کند: نه blur، نه opacity، نه
`display:none`، و ظرف `overflow-hidden` اطراف قیمت هم در عرض دسکتاپ آن را برش نمی‌دهد. هر دو
نسخه سمت سرور رندر می‌شوند و نشانه‌های `<!---->` اطرافشان لنگرهای شاخه‌ای Vue هستند، نه جای‌نگهدار
هیدریشن.

**لنگر انتخابگر، کلمه «تومان» است — نه هیچ کلاسی.** این عمدی است: رشته «تومان» در کل سند **دقیقاً
یک بار** می‌آید (کلمه «ریال» اصلاً در صفحه نیست) و قیمت، خواهرِ بلافاصله قبل از آن است. انتخابگر
کلاسی باید از یک میدان مین انتخاب کند: کلاس `.tabular-nums` — گزینه طبیعی — روی این صفحه **۱۵ عنصر**
می‌گیرد.

آن پانزده عنصر و دلیل رد شدن هر کدام:

| مقدار | چیست | چرا نباید خوانده شود |
| --- | --- | --- |
| `84,878.01` `2,682.17` `774.27` `0.09284` `1.20` | بیت‌کوین، اتریوم، بایننس، دوج و پولکادات در منوی بالای صفحه | **ارقام لاتین، کامادار، غیرصفر** — خطرناک‌ترین رشته‌های این صفحه. فقط `display:none` والدِ آن‌ها (که rect صفر می‌دهد) آن‌ها را از حکم بیرون نگه می‌دارد |
| `۱ USDT` | «قیمت تتر به تتر»، پگ دلاری | غیرصفر، و **همان کلاس `.tabular-nums`** را دارد؛ فقط نداشتن کاما نجاتش می‌دهد |
| `۱۸۳,۸۷۰,۶۸۳,۹۹۸.۹۲` | ارزش کل بازار | کامادار **با اعشار**، دقیقاً با همان سبک رقمِ قیمت. regex نمی‌تواند ردش کند؛ **فقط انتخابگر می‌تواند** |
| `۲۲,۸۳۱,۱۵۰,۴۲۵` `۷۲۱,۶۷۲,۶۳۱` `۲۰۸,۳۱۲,۴۵۶` | ارزش بازار بیت‌کوین، اتریوم و بایننس | کامادار، در همان فهرستی که قیمت تکراری در آن است |
| `۲۶۹K` `۲۶۸K` `۲۶۶K` … | برچسب محور نمودار | جداکننده ندارند و طبق سیاست بررسی نمی‌شوند |
| `—` و سه `input` خالی | ماشین‌حساب | جای‌نگهدار خالی |

نکته: خانه «بیشترین قیمت» در نسخه زنده مقدار `$۱` نشان می‌دهد — این یک ایراد داده در سایت خودشان
است، نه پنهان‌سازی، و قیمت تومان هم نیست.

**بررسی‌نشده:** نمودار `1D/1W/1Y/1H`. برچسب محورش قیمت لحظه‌ای نیست و مسیر رسم‌شده یک منحنی است،
نه عددی خوانا — همان قاعده تبدیل و ارزپلاس. کلید تعویض بازه هم کلیک نمی‌شود؛ فقط چهار برچسب و
یک نشانگر تزئینی دارد.

**فهرست «ارزهای دیگر» دیر رندر می‌شود.** در DOM اولیه نیست و بعد از هیدریشن ظاهر می‌شود (۱۵ عنصر
`.tabular-nums` می‌شوند، نه ۱۱). آداپتوری که تا آماده شدن صفحه صبر می‌کرد، در هر
نمونه‌برداری سریع این صرافی را «نامشخص» گزارش می‌کرد؛ بنابراین این probe **اختیاری** است: وقتی
نیست فقط `null` می‌دهد و سربرگ تصمیم می‌گیرد.

**نکته‌ای که ارزش ثبت شدن دارد: اینجا هیچ نشت داده‌ای در payload نیست.** برخلاف هر Nuxt دیگری که
در این مجموعه پایش می‌کنیم، `__NUXT_DATA__` همتاپی **اصلاً قیمتی ندارد**: هر سه store یک شیء
`NuxtError` با `statusCode:404` هستند و `prices.byMarket` یک شیء خالی است. قیمت فقط در HTML رندرشده
وجود دارد. این را صریح ثبت می‌کنیم چون **نبودِ نشت داده دلیل رعایت دستور نیست** — این صفحه قیمت
را جلوی چشم نشان می‌دهد و در payload چیزی لو نمی‌دهد.

**API عمومی:** `hamtapay.net/api/bus/client/prices` روی دامنه خودِ سایت، بدون احراز هویت و بدون
**هیچ هدری** (با `User-Agent` و `Accept` که صریحاً پاک شده بودند هم پاسخ ۲۰۰ داد). آداپتور فقط
`market_price` را می‌خواند، چون همان شیء **سه عدد باورپذیر** دارد: `sell` و `buy` که مرزهای دفتر
سفارش با ۲۷ رقم اعشارند، و `avg` که یک میانگین متحرک است و به قیمت نزدیک است ولی عمداً با آن فرق
دارد. واحد هم از خودِ فید گرفته می‌شود: `quote_name` برابر `"Toman"` است و در میان ۶۰۷ نمادِ API
اصلاً جفتِ ریالی وجود ندارد.

### ایرادی که همتاپی آشکار کرد: تصویرهای شواهد بلافاصله پاک می‌شدند

اولین اجرای زنده درست گزارش شد (تخلف، `۲۶۹,۰۷۴` تومان، و `market_price` دقیقاً همان عدد) — اما **هیچ
تصویری ذخیره نشده بود**. علت در هیچ‌کدام از کدهای آداپتور نبود:

`pruneShots()` نام فایل‌ها را **به‌صورت رشته** مرتب می‌کرد. نام‌ها به شکل
`` `${id}-${kind}-${epochms}.png` `` هستند، پس مرتب‌سازی رشته‌ای اول آن‌ها را بر اساس **شناسه صرافی**
گروه‌بندی می‌کند. به‌محض پر شدن پوشه (۶۰ فایل)، حلقه حذف **تازه‌ترین** تصویرهای صرافیِ
اولِ فهرست (از نظر الفبایی) به‌عنوان «قدیمی‌ترین» پاک می‌کرد و تصویرهای کهنهٔ صرافی‌های
آخرِ فهرست (از نظر الفبایی) را نگه می‌داشت — یعنی شواهدی که همین لحظه گرفته شده بودند ناپدید می‌شدند.

اصلاح: مرتب‌سازی بر اساس **مهر زمانی داخل نام فایل**، نه خود رشته. بعد از اصلاح، هر دو تصویر
همتاپی باقی ماندند و پوشه همچنان روی ۶۰ فایل نگه داشته شد.

## ارزینجا: پنج جای نمایش قیمت، و دو تکنیکی که اینجا شکست می‌خورند

ارزینجا قیمت تتر را در **پنج جای یک صفحه** منتشر می‌کند و هیچ‌چیز را پنهان نمی‌کند: در کل سند
صفر `opacity-0`، صفر `filter`، صفر `backdrop-filter`، صفر `display:none`، صفر blur و صفر mask
وجود دارد. همه قیمت‌ها متن ساده و رندرشده سمت سرور هستند.

| # | محل | لنگر انتخابگر |
| --- | --- | --- |
| ۱ | بلوک `#price` («قیمت تتر امروز») | `#price span.font-bold.tabular-nums` |
| ۲ | کارت «قیمت لحظه ای تتر» | متن `<h3>` خودش → `<p>` بعدش |
| ۳ | نرخ معامله آنی | `۱ USDT = … IRT` — با لنگر دوطرفه |
| ۴ | ردیف «آخرین قیمت تتر به تومان» | متن `<h3>` خودش → خواهر بعدش |
| ۵ | جدول بازار «بازارهای معاملاتی تتر» | سلول نماد `IRT` → خواهر بعدش |

**دو تکنیکی که روی صرافی‌های قبلی جواب داد، اینجا شکست می‌خورد** — و هر دو دامش روی همین صفحه
است:

**۱. کلمه «تومان» اینجا لنگر نیست.** روی همتاپی این کلمه دقیقاً یک عنصر را نشان می‌کرد؛ اینجا
**۴۶ بار** در markup رندرشده می‌آید: در `<title>`، در meta keywords، در پنج پاراگراف متن، در
`placeholder` یک input، در دو `alt` تصویر، در برچسب جفت ارز، و در یک عدد قدیمی داخل متن. یعنی
یک تست که روی «تکرار یکتایی کلمه تومان» تکیه کند، روی سایت بعدی می‌شکند.

**۲. کلاس `.tabular-nums` اینجا تله است، نه میان‌بر.** دقیقاً دو عنصر می‌گیرد و **اولی پگ دلاری
است**:

```html
<span class="… tabular-nums">(۱دلار)</span>
<span class="font-bold text-xl … tabular-nums">۲۶۸,۵۰۵ تومان</span>
```

یعنی `querySelector('.tabular-nums')` روی این صفحه **پگ دلاری** برمی‌گرداند، نه قیمت. آداپتور
به همین دلیل `.font-bold` را هم شرط می‌کند. هر دو نکته با تست قفل شده‌اند تا کسی بعداً انتخابگر را
«ساده‌تر» نکند.

**نزدیک‌ترین دام‌ها، دو استیبل‌کوین همسایه‌اند.** زیر «رمزارز های مشابه» دو استیبل‌کوین با همان
دارایی و همان واحد `IRT` فهرست شده‌اند:

| ارز | مقدار | فاصله تا قیمت واقعی |
| --- | --- | --- |
| TUSD | `۲۶۸,۴۵۱ IRT` | ۵۴ تومان |
| USDC | `۲۶۸,۵۵۸ IRT` | ۵۳ تومان |

همان شش رقم، همان کاما، همان برچسب `IRT`، همان صفحه. در markup هیچ چیز آن‌ها را از ردیف تتر
جدا نمی‌کند جز `href` — و به همین دلیل همه probeها روی **عنوانِ قابل مشاهده** لنگر شده‌اند، نه روی
متنِ قیمت. بالاترین (`۲۶۹,۵۸۵`) و پایین‌ترین (`۲۶۲,۶۰۵`) ۲۴ ساعته هم دقیقاً همین شکل را دارند،
و شبکه آمار کنار نمودار سه عدد کامادارِ غیرصفر دیگر:
`۹۷,۵۱۹,۷۸۷,۶۳۱.۰` و `۱۸۴,۰۲۳,۸۶۹,۳۵۸.۰` و `۱۸۴,۰۵۷,۷۱۳,۹۸۳.۹۳`.

**دامی که داخل متن است:** تنها جداکننده U+066C در کل سند، متعلق به یک عدد **قدیمی و ویرایشی**
است — «حدود **۹۰٬۷۸۸ تومان**» در یک پاراگراف. همه قیمت‌های زنده از کامای لاتین استفاده می‌کنند.
چون الگوی ما هر دو جداکننده را می‌پذیرد، **فقط انتخابگرها** هستند که این پاراگراف را از حکم
بیرون نگه می‌دارند.

**جدول بازار عدد متفاوتی برای همان جفت دارد:** `۲۶۸,۷۵۰` در برابر `۲۶۸,۵۰۵`. این هم یک افشای
قیمت تتر است و به همین دلیل probe مخصوص خودش را دارد. ضمناً خانه قیمت در `hidden lg:block` است و
کلاس `.text-spec-currency-price` را **خانه حجم معاملات هم** دارد — برای همین قیمت از راه خواهر
سلول نماد `IRT` پیدا می‌شود، نه با query کردن آن کلاس.

**بررسی‌نشده:** نمودار یک `<iframe>` از TradingView است و چیز خواندنی ندارد؛ طبق همان قاعده
تبدیل، ارزپلاس، سرمایکس و همتاپی کنار گذاشته می‌شود. کلید «بازار ارزینجا / بازار جهانی» هم هیچ
گره قیمتی همسایه ندارد و کلیک نمی‌شود.

**`__NEXT_DATA__` در این صفحه گمراه‌کننده است:** با `"page":"/"` و `gssp:true` یعنی payload
**صفحه اصلی** است، نه صفحه تتر؛ و `USDTIRT.stats.lastPrice` در آن `267990` است که با `۲۶۸,۵۰۵`
روی صفحه نمی‌خواند. هیچ‌چیز از آن خوانده نمی‌شود و یک تست هم قفل می‌کند که آن عدد هرگز برگردانده
نشود.

**API:** عمداً ندارد. فید عمومی و بدون احراز هویت وجود دارد، اما `robots.txt` سایت `Disallow: /api`
دارد — این تصمیم در بخش «مقایسه با API عمومی» هم ثبت شده. در نتیجه **تصویر شواهد تنها مدرک ماست**.

## ایران اکسچنج: یک نرخ، دو قالب رقم، و ردیفی که معمولاً نیست

ایران اکسچنج برخلاف بقیه یک داشبورد صرافی نیست؛ یک صفحه بازاریابی برای خرید تتر است. نرخ را
ساده منتشر می‌کند و هیچ‌چیز را پنهان نمی‌کند: صفر `backdrop-filter`، صفر `visibility:hidden`، صفر
`clip-path`، صفر mask، و نه blur و نه opacity روی قیمت یا والدهایش. صفحه کاملاً سمت سرور رندر
می‌شود، پس مسئله رقابت با هیدریشن هم در کار نیست.

**همان نرخ، در دو قالب رقم کاملاً متفاوت:**

| محل | مقدار | ارقام | جداکننده |
| --- | --- | --- | --- |
| ویجت تبدیل بالای صفحه | `۲۶۸٬۱۰۰` تومان | فارسی | **U+066C** |
| جدول بازار | `268,800` تومان | لاتین | `,` |

و بدتر از آن: **این دو مقدار با هم اختلاف دارند.** ویجت دنبال `sellToIranicardCurrencyPrice` است و
جدول عددی جداگانه‌دارد. هر دو افشای نرخ تترند، پس هر دو بررسی می‌شوند — و هیچ probeیی نباید
فرض کند یکی هستند یا یک عددند.

**نکته‌ای که فقط در بررسی زنده معلوم شد و در HTML ارسالی شما نبود: جدول بازار معمولاً اصلاً تتر را
فهرست نمی‌کند.** روی نسخه زنده، جدول پیش‌فرض ۲۴ رمزارز را نشان می‌دهد و تتر بینشان نیست (فهرست
تب‌بندی و صفحه‌بندی دارد، پس محتوایش جابه‌جا می‌شود). ردیف تتر همچنان بررسی می‌شود چون در یکی از
گرفته‌های قبلی وجود داشت — ولی **اختیاری** است، و نبودنش هرگز نباید صفحه‌ای را که واضحاً قیمت را
نشان می‌دهد به «نامشخص» تبدیل کند.

وقتی ردیف هست، کار سخت است: قیمت در **سه** سلول رندر می‌شود — دو ستون دسکتاپ («قیمت خرید» و «قیمت
فروش») که فهرست کلاسشان **بایت‌به‌بایت یکسان** است و فقط با موقعیت از هم جدا می‌شوند، و یک کپی
دیگر در سلول موبایل با `sm:hidden` که در عرض ۱۴۴۰ اصلاً رندر نمی‌شود. تنها تفاوت قابل اتکا این
است که دو سلول دسکتاپ قیمتشان را در `<a aria-label="USDT">` پیچیده‌اند و سلول موبایل ندارد. یک تست
این نامتقارنی را قفل می‌کند و تست دیگری ثابت می‌کند `children[1]` واقعاً ستون «قیمت خرید» است.

**کلمه «تومان» اینجا هم بی‌فایده است:** بیش از صد بار می‌آید، ۷۲ بارش فقط برچسب خالی
`<span>تومان</span>` داخل خود جدول است. ویجت به‌جای آن با رابطهٔ والد-فرزند پیدا می‌شود: یک
`<p>` قیمت که خواهر بعدی‌اش دقیقاً «تومان» است، در ردیفی که «تتر» را هم نام برده.

**نزدیک‌ترین دام صفحه:** کارت **USDS** با `۲۶۹٬۲۶۰` — دقیقاً همان قالب ویجت (فارسی + U+066C)،
در فاصله ۴۶۰ تومان. و در همان جدول، **USDC** با `۲۶۸٬۶۸۹` تومان نقل شده که با همان حسابِ پگ دلاری
عملاً نرخ تتر را لو می‌دهد. هیچ‌کدام خوانده نمی‌شود چون پایش ما per-asset روی خود USDT است — ولی
این روشن‌ترین نمونهٔ همان پرسشی است که این ابزار نمی‌تواند به‌جای شما تصمیم بگیرد.

**ثبت‌شده ولی بررسی‌نشده:** بلوک schema.org در `<head>` قیمت دارد
(`"price":2688000, "priceCurrency":"IRR"` — یعنی ۲۶۸,۸۰۰ تومان، کاملاً درست از نظر واحد) و payload
ریکت هم `sellToIranicardCurrencyPrice` را دارد. هیچ‌کدام رندر نمی‌شوند، پس طبق همان قاعده
کیف پول من و رمزینکس، نشت داده **یادداشت** است نه probe.

**API:** ندارد — سومین آداپتور بدون API پس از پول نو و ارزینجا. دلیلش در بخش «مقایسه با API عمومی»
ثبت شده. در نتیجه **تصویر شواهد تنها مدرک ماست**.

## عصر تتر: دو کپیِ واکنش‌گرا، و یک قیمتِ کهنه در متن

عصر تتر یک سایت مرجع قیمت است، نه داشبورد صرافی — و اولین صفحه‌ای در این مجموعه که قیمتش **عمداً
دو بار** وجود دارد. هیچ‌چیز را پنهان نمی‌کند: نه `filter`، نه `opacity`، نه mask، نه `clip-path`، نه
blur روی هیچ‌کدام از دو کپی. صفحه کاملاً سمت سرور رندر می‌شود، پس مسئله رقابت با هیدریشن نیست.

| کپی | کلاس واکنش‌گرا | در ۱۴۴۰ پیکسل | در ۹۰۰ پیکسل |
| --- | --- | --- | --- |
| کارت موبایل | `xl:hidden` | **پنهان** | **نمایان** |
| کارت دسکتاپ (چسبان) | `max-xl:hidden` | **نمایان** | **پنهان** |

هر دو همیشه در DOM هستند و markup داخلی‌شان **بایت‌به‌بایت یکسان** است. در بررسی زنده تأیید شد:
در ۱۴۴۰ کارت اول جعبه‌ای با اندازه صفر زیر یک والد `display:none` می‌شود و کارت دوم روی صفحه است؛
در ۹۰۰ دقیقاً جابه‌جا می‌شوند.

**به همین دلیل هر دو بررسی می‌شوند و داوری را به بررسی قابلیت دیدن می‌سپاریم**، نه به حدس درباره
اینکه کدام‌یک در این عرض نمایان است. اگر «کارت دسکتاپ» را ثابت فرض می‌کردیم، تا لحظه‌ای که breakpoint
جابه‌جا شود درست کار می‌کرد و بعد **حکم وارونه می‌شد**: قیمتی که جلوی چشم است «پنهان» گزارش می‌شد.
بررسی هر دو، این خرابی را ناممکن می‌کند. یک تست صریح هم جابه‌جایی را در هر دو عرض ثابت می‌کند تا
مشخص باشد این طراحی تزئینی نیست.

کارت پنهان در صفحه‌ای که «رعایت‌شده» داوری شود، به‌صورت یادداشت گزارش می‌شود — و آن یادداشت
**راست** است، پس سرکوبش نمی‌کنیم.

**تله‌ها.** سه‌تایشان کامادار و غیرصفرند:

| دام | مقدار | چه مشکلی می‌سازد |
| --- | --- | --- |
| بالاترین / پایین‌ترین ۲۴ ساعت | `273,361` / `260,190` | همان شکل شش‌رقمی قیمت. و بالاترین **سه بار** تکرار شده — یک کاشی و دو بار در جدول اطلاعات بازار |
| **قیمت کهنه در متن راهنما** | `۱۲۳,۹۹۵ تومان` | در JSON-LD و متن FAQ نوشته شده: *«در زمان نگارش این مطلب، هر تتر برابر با ۱۲۳,۹۹۵ تومان است»* — **ارقام فارسی + کامای لاتین + خودِ کلمه تومان**. دقیقاً همان قالبی که الگوی ما می‌پذیرد، و حدود نیمی از نرخ زنده |
| کارت پگ دلاری | `۱` / `USDT` | با عنوان «آخرین قیمت تتر به **تتر**» — هم‌سایهٔ عنوان کارت اصلی |

نشان درصد تغییر `0<!-- -->%` است: یک جداکنندهٔ گره متنی ریکت بین عدد و علامت می‌افتد و تطبیق متنی
`>\d+%` را از کار می‌اندازد.

«تومان» **۶۲ بار** می‌آید (هفت بارش فقط در `<head>`)، پس لنگر نیست. هر probe روی عنوان کارت خودش —
«آخرین قیمت تتر به تومان» — لنگر می‌شود و قیمت از داخل همان کارت پیدا می‌شود؛ به این ترتیب عنوان
هم‌سایهٔ کارت پگ هرگز با آن اشتباه نمی‌شود و یک تغییر نام کلاس هم نمی‌تواند probe را جابه‌جا کند.

**نموداری اصلاً رندر نمی‌شود:** نه `<canvas>`، نه `<text>` داخل SVG درون‌خطی، نه embed شخص ثالث. کارت
«نمودار قیمت» به یک لوگوی کم‌رنگ تبدیل می‌شود، پس اصلاً برچسب محوری برای کنار گذاشتن وجود ندارد.
سه تصویر `storage.asretether.com/price/usdt/*.webp` هم تصویر نوشتاری‌اند نه اسکرین‌شات قیمت (متن
جایگزینشان «عوامل موثر بر قیمت تتر» و مانند آن است) و رقم‌هایشان رستر است، نه متن DOM.

**ثبت‌شده ولی بررسی‌نشده:** payload ریکت علاوه بر `price_buy` (همان عدد نمایشی، بدون کاما) یک
`price_sell` هم دارد — **یک قیمت تومانِ دوم و متفاوت که هیچ‌جا رندر نمی‌شود**، چون بازار بسته است
(`is_open:false`) و دو طرف حدود ۲۵۰۰ تومان اختلاف دارند. طبق همان قاعده کیف پول من، رمزینکس و
ایران اکسچنج، نشت داده یادداشت است نه probe — و یک تست قفل می‌کند که هیچ‌کدام از این دو عدد هرگز
برگردانده نشود.

**API:** ندارد — چهارمین آداپتور بدون API. دلیلش در بخش «مقایسه با API عمومی» ثبت شده است.

## هیتوبیت: تنها یک قیمت، و شناسه‌هایی که دروغ می‌گویند

هیتوبیت ساده‌ترین صفحهٔ این مجموعه است: قیمت تتر فقط **یک جا** نمایش داده می‌شود، به‌صورت متن
ساده، و هیچ پنهان‌سازی‌ای در کار نیست — نه opacity، نه filter، نه mask، نه clip، نه blur، و نه
کلاسِ پنهان‌سازیِ واکنش‌گرا در هیچ‌کدام از والدهایش.

```html
قیمت بازار:  <span id="last-usdt-price">269,033</span>تومان
```

`#last-usdt-price` یک شناسهٔ پایدار است که **CSS خودِ سایت** روی آن هدف گرفته
(`.ttr-price1 a #last-usdt-price { color:#FCAF17; font-weight:600 }`)، و در markup **دقیقاً یک
عنصر** دارد. واحد، یک گره متنیِ برهنهٔ «تومان» بعد از span است — نه یک عنصر — پس انتخابگری
ندارد، ولی probe وجودش را بررسی می‌کند.

**یک رفتار زمانیِ واقعی، و flash نیست:** span در HTML اولیه با خط تیره (`–`) رندر می‌شود و
اسکریپت خودِ سایت حدود ۱.۵ ثانیه بعد آن را از فید تیکر پر می‌کند. اندازه‌گیری زنده:

| زمان | محتوای span |
| --- | --- |
| ۰ میلی‌ثانیه | `" – "` |
| ۱۵۰۰ میلی‌ثانیه | `"269,033"` |

این دقیقاً همان چیزی است که حلقهٔ settle از قبل درست انجام می‌دهد — **آخرین قرائت برنده است** — پس
نه جای‌نگهدار با وضعیت نهایی اشتباه گرفته می‌شود و نه قیمت واقعی با flash. هیچ کدِ خاصی لازم نیست؛
ثبت شده چون دلیلِ این است که **پنجرهٔ settle نباید کوتاه شود**، و کوتاه شدنش این صرافی را خاموش و
«رعایت‌شده» گزارش می‌کرد.

**دام‌ها** — و نکتهٔ جالب اینجاست که هیچ‌کدامشان از طریق این شناسه **در دسترس نیست**، و همین
دلیلِ کارِ انتخابگر است:

| دام | مقدار | چه مشکلی می‌سازد |
| --- | --- | --- |
| سلول‌های `.quote-sign` جدول بازار | `2,683.310000000000` | **کامادار و غیرصفر** — قیمت دلاری اتریوم با دوازده رقم اعشار. یک جست‌وجوی متنی `2,683` را بیرون می‌کشد. ضمناً این کلاس روی سلول‌های درصد و حجم هم هست |
| ستون تومان جدول | `20.02 هزار تومان`، `721.90 میلیون تومان` | با یک کلمهٔ بزرگی‌نمای فارسی کوتاه شده، پس اصلاً با عدد کامادار جور در نمی‌آید — ولی این شانس است، نه طراحی |
| **`#dominance-btc` و `#market-cap` جابه‌جا** | `$ 3.30 T` و `% 63.69` | **ایراد واقعی خودِ سایت:** شناسه‌ای که به اسم دامیننس بیت‌کوین است، در واقع ارزش بازار را نگه دارد و برعکس. یک تست این را قفل می‌کند تا fixture ایراد آن‌ها را ثبت کند نه اینکه بی‌سروصدا درستش کند |
| شمارنده‌های ساده | `99`، `151`، `+۵۰`، `3` | غیرصفر، و هیچ‌کدام قیمت نیست |

نکتهٔ مهم دیگر: **جدول بازار اصلاً ردیف `USDT/IRT` ندارد.** هر پنج جفت آن (SAND، ETH، ENJ، ETC،
PAXG) به دلار قیمت‌گذاری شده‌اند، پس رشتهٔ «USDT» فقط داخل برچسب جفت‌ها می‌آید
(`SAND/USDT` و مانند آن) و نه جای دیگر. یک تست که می‌گوید «آیا این ردیف به USDT اشاره دارد؟»
نباید برای اثبات وجود قیمت تتر قابل اعتماد باشد.

**ثبت‌شده ولی بررسی‌نشده:** نه نموداری وجود دارد (تنها `<canvas>` یک QR code پنهان برای دانلود
اپلیکیشن است)، نه قیمتی در هیچ meta یا JSON-LD، و نه قیمتی در هدر، هیرو، فوتر یا نوار کناری.
کلمات چرخان تیتر (`.words-1`) هم «قیمت / پشتیبانی / تنوع رمزارز» هستند و عددی ندارند. چند شناسهٔ
CSS روی این صفحه **مرده** هستند (`#list-price`، کلاس `.last-usdt-price`، `#ycd-circle-4148`) و
نباید با قلاب‌های زنده اشتباه گرفته شوند.

**API:** ندارد — پنجمین آداپتور بدون API. دلیلش در بخش «مقایسه با API عمومی» ثبت شده است.

## اتراکس: چهار جای نمایش، و متنی که با ثابت‌کردن رنگ می‌شود

**به‌روزرسانی:** اتراکس صفحهٔ تترش را کلاً غیرفعال کرده و همان مسیر با وضعیت ۵xx پاسخ می‌دهد. طبق
تصمیم صریح، این وضعیت **رعایت دستور** ثبت می‌شود — صفحه‌ای که باز نمی‌شود قیمتی هم برای نمایش
ندارد — و صفحهٔ جایگزین «بازار معاملاتی» هرگز داور نمی‌شود. توضیح زیر، حالت قبلی صفحه را توصیف
می‌کند که آداپتور برای روزی که صفحه دوباره باز شود همچنان نگه می‌دارد.

اتراکس یک صفحهٔ تک‌رمزارزی است: نه جدول مقایسه، نه نوار بازار، نه فهرست رمزارزهای دیگر. پس هیچ
قیمتِ همسایه‌ای وجود ندارد که با نرخ تتر اشتباه شود. نرخ در **چهار جا** و با **دو سیستم رقم**
منتشر می‌شود:

| # | محل | مقدار | ارقام |
| --- | --- | --- | --- |
| ۱ | بنر اصلی | `268,400` تومان | لاتین، کامای لاتین |
| ۲ | فیلد `#irtAmount` | `value="268,400"` | لاتین، کامای لاتین |
| ۳ | ردیف «نرخ تبدیل» | `۲۶۸٬۴۰۰` | **فارسی، U+066C** |
| ۴ | آمار «قیمت تومانی» | `۲۶۸٬۴۰۰ تومان` | **فارسی، U+066C** |

هر دو قالب واقعاً هم‌زمان روی نسخهٔ زنده استفاده می‌شوند (بررسی شد)، پس الگو باید هر دو را بپذیرد
و هیچ probeیی نباید فرض کند سایت یکدست است.

### یافته‌ای که ارزش ثبت شدن دارد: قیمت بنر با گرادیان رنگ می‌شود

هر span روی خط قیمت بنر به‌صورت inline این‌ها را دارد:

```
color: transparent;  -webkit-text-fill-color: transparent;  background-clip: text;
```

و رنگ قرار است از یک گرادیان بیاید. **در HTML ارسالی شما آن گرادیان خالی سریال شده بود**
(`background-image: ;`). با یک مقدار خالیِ نمایشی و رنگ شفاف، خوانندهٔ منصفی می‌تواند نتیجه بگیرد که
رقم‌ها اصلاً نقاشی نمی‌شوند — یعنی قیمت پشت شفافیت پنهان شده است.

اندازه‌گیری در مرورگر واقعی نشان می‌دهد **این برداشت اشتباه است**:

| ویژگی | مقدار واقعی |
| --- | --- |
| `color` | `rgba(0, 0, 0, 0)` |
| `-webkit-text-fill-color` | `rgba(0, 0, 0, 0)` |
| `background-image` | `linear-gradient(rgb(0,0,0) 0%, rgb(128,128,128) 100%)` |
| `background-clip` | `text` |

رقم‌ها از راه گرادیان نقاشی می‌شوند و کاملاً خوانا هستند. بنابراین بنر هم مثل بقیه بررسی می‌شود.

دو نتیجه که صریح ثبت شده‌اند و پنهان نمانده‌اند:

- **DOM کپی‌شده روی این سایت دلیلِ رنگ‌شدن نیست.** هر بررسی آینده باید استایل محاسبه‌شده را در
  مرورگر زنده بخواند، نه استایل inline سریال‌شده را.
- `visibility.js` عمداً `display`، `visibility`، `opacity` و `filter` را بررسی می‌کند و **`color`
  را نه**. اینجا درست است — وگرنه متنِ گرادیان‌دار را نامرئی می‌خواند — اما در نتیجه متنی که واقعاً
  شفاف و بی‌پس‌زمینه است هم «نمایان» گزارش می‌شود. هیچ صرافی دیگریِ تحت نظارت از این تکنیک
  استفاده نمی‌کند، پس **چیزی تغییر نکرده**؛ این یک شکاف شناخته‌شده است، نه مسئلهٔ حل‌شده.

### برخورد کلاس‌ها

عدد `1` بنر (مقدار USDT) فهرست کلاسی **بایت‌به‌بایت یکسان** با span قیمت دارد:

```
text-[24px] text-grayscale-07 leading-[36px] font-[700]
```

پس هر انتخابگر کلاس‌محور برای قیمت، همان مقدار را هم می‌گیرد. به همین دلیل **هیچ‌چیز اینجا با کلاس
پیدا نمی‌شود**؛ هر محل با عنوان خودش، با `id` خودش، یا با رابطهٔ خواهر-برادر لنگر می‌شود. خودِ قیمت
بنر هم با **شکل** پیدا می‌شود — یک عدد کامادار که خواهرِ بعدی‌اش دقیقاً «تومان» است — چون این
ترکیب در صفحه یک بار می‌آید. (آمار «قیمت تومانی» واحدش را داخل همان عنصر دارد، نه به‌صورت خواهر،
پس این دو هرگز اشتباه نمی‌شوند.)

**فیلد `#irtAmount` بررسی می‌شود ولی عکس‌برداری نمی‌شود:** مقدارش در پراپرتی `value` است نه در متن
DOM، و `innerText` یک `<input>` همیشه خالی است — پس تصویری از آن هرگز نمی‌تواند مقدار را نشان دهد.

هیچ‌چیز دیگری در این صفحه با نرخ تتر اشتباه نمی‌شود: `$1.00` (قیمت دلاری، اعشار نقطه‌ای)، سه تا
`1` (مقدارها)، `—` (تغییرات ۲۴ ساعته، جای‌نگهدار خط تیره)، `نامحدود` (عرضه، عمداً غیرعددی)، چهار
عدد گرادیانی مرحله `۱ ۲ ۳ ۴`، و کارمزد `0.02%`. فقط `268,400` و `۲۶۸٬۴۰۰` در کل سند کامادارند.

**ثبت‌شده ولی موجود نیست:** هیچ قیمتی در `<script>`، در payload خام ریکت (فقط بارگذاری chunkها)، در
هیچ meta، و **اصلاً هیچ بلوک JSON-LDی وجود ندارد**. هیچ قیمتی داخل آکاردئون بسته نیست. نمودار یک
`<iframe>` بین‌دامنه‌ای به `app.eterex.com` است.

**API:** ندارد — ششمین آداپتور. فید این سایت بررسی نشد، پس چیزی دربارهٔ آن ادعا نمی‌شود.

## واحد قیمت

هر صرافی قیمت را با واحد خودش نمایش می‌دهد. بیت‌پین و نوبیتکس قیمت را به **تومان** و رمزینکس به **ریال** نشان می‌دهند؛ واحد از آداپتور خوانده و در همه جاها (کارت، صفحه جزئیات و متن توضیح) درست نمایش داده می‌شود. مقایسه با API همیشه به تومان تبدیل می‌شود.

## افزودن صرافی جدید

هر صرافی یک آداپتور مستقل در `src/exchanges/<name>.js` است که فقط باید دو چیز فراهم کند:

```js
module.exports = {
  id, name, host, coin, market, url,
  api: { url, parse(json) },        // اختیاری
  probeInPage({ coin }) {           // داخل صفحه اجرا می‌شود
    // تگ کردن عناصر برای اسکرین‌شات
    document.querySelectorAll('[data-monitor]').forEach((e) => e.removeAttribute('data-monitor'));
    el.dataset.monitor = 'row';
    return {
      ready: true,                  // آیا بخش قیمت پیدا شد؟
      feedLive: true,               // آیا صفحه کامل بارگذاری شد؟
      probes: [{ key, label, raw, primary }],
      shots:  [{ key, label }],
    };
  },
};
```

سپس آن را در `src/exchanges/index.js` اضافه کنید. بقیه برنامه — داوری، آمار، داشبورد و هشدارها —
خودکار با صرافی جدید کار می‌کند.

## API

| مسیر | توضیح |
| --- | --- |
| `GET /api/status` | وضعیت کلی + وضعیت و آمار همه صرافی‌ها. شامل `browserHealth` است: آیا این سیستم اصلاً می‌تواند مرورگر را اجرا کند یا نه (و اگر نه، چه فرمانی لازم است). |
| `GET /api/logs` | گزارش رخدادها با `level` و `exchange` و `limit`. هر رخداد `meta` هم دارد: خوانش‌های صفحه، سیاست مؤثر، و خطای شبکهٔ دسته‌بندی‌شده. |
| `GET /api/logs/report` | گزارش کامل اشکال‌زدایی به‌صورت متن ساده: پیکربندی مؤثر، کانال واقعی مرورگر، و همهٔ رخدادها به‌صورت JSON. مناسب برای چسباندن در issue. |
| `POST /api/logs/clear` | خالی کردن فهرست رخدادها. شمارنده‌های «از ابتدای اجرا» دست‌نخورده می‌مانند. |
| `GET /api/exchange/:id` | گزارش، آمار و تاریخچه یک صرافی در یک درخواست |
| `GET /api/history?limit=40` | تاریخچه ترکیبی همه صرافی‌ها |
| `POST /api/check` | بررسی فوری همه صرافی‌ها |
| `POST /api/check/:id` | بررسی فوری فقط یک صرافی |
| `POST /api/interval` | تغییر فاصله بین بررسی‌ها (`{ "seconds": 600 }`) |
